# DSH 模型路由器

本文是 [README.md](README.md) 的中文翻译；英文原文为准。

这是一个仅在 DSH 主机端运行的插件。它将每个新用户任务评为 1 至 5 级，选择已配置的提供商、模型与推理强度，并记录实际 token 用量、延迟、现金成本、订阅配额和可选用户反馈。分类在本地按确定规则执行，不会增加模型调用。

## 构建与安装

```sh
cd plugins/model-router
npm ci
npm run check
dsh plugin --profile superagent add "$PWD"
```

桌面配置使用 `--profile desktop`。按默认配置安装时，插件只测量主要会话请求，不更换模型。要启用路由，请把 `model-router` 配置加入该配置的 `cordis.patch.yml`。[example.patch.yml](example.patch.yml) 只是起点，不是可直接采用的价格表。未启用 HMR 的配置需要重启 DSH。

## 路由

使用兼容的 Superagent 分支时，在路由器配置中加入 `sourceKinds: [user, dsh-superagent]`，并配置可选模型。路由只处理新的工作任务，不处理状态消息或普通转发。用户明确指定的模型优先；没有合适的路由时，工作会话保留当前模型（新会话使用 Executor 默认模型）。

每个模型需要声明：

- `capability` 与 `speed`：1 至 5 的相对整数评分。
- `input`：`text`、`image` 或两者。
- `reasoningEfforts`：该具体路由接受的强度。
- `contextWindow`：可选输入上限，用于排除预计提示无法容纳的路由。
- `billing`：按量付费价格，或带配额权重的订阅引用。

策略如下：

- `balanced`：按权重比较质量、速度、等值成本与配额保留。
- `cash`：先比较预计边际现金成本，再比较均衡效用。订阅请求的边际现金成本为零。
- `subscription`：优先可用订阅路由，再比较预计配额消耗。
- `quality`：优先能力评分最高的模型。
- `speed`：优先速度评分最高的模型。

默认分类器组合可配置的文本信号、长度阈值与附件权重。`effortByScore` 指定期望强度；路由选择最接近的已支持级别，距离相同时选择较低级别。启动时通过不发送请求的 DSH `prepareCall` 检查排除不可用模型和不支持的强度，并记录警告。已卸载图片按文本而非视觉输入计算。任务被领取时、DSH 读取该步骤模型选择之前完成路由，因此排队任务可分别选择路由。工具后续步骤保留已选路由。没有合适模型时，插件保留当前选择并记录警告。

默认权重为质量 35、速度 20、现金 25、配额 20。均衡成本使用按量付费预估值；已知订阅窗口费用和配额上限时，也使用分摊订阅价值。可按所需权衡调整权重。

## 仪表盘

Web 客户端会在 DSH 左侧栏添加 **Model routes**。仪表盘显示实际请求总量、结果、近期每日输出用量、精确现金与当前窗口配额、路由效率、用户评价成功率和健康状态。刷新只读取仅限所有者的已认证主机端点，不发送模型请求。**Pause routing** 暂停自动模型选择，但不停止计量或健康监控。支持加载、空数据、错误、窄屏和正常数据状态。

## 命令

- `/model-route` 或 `/model-route status`：自动状态、当前模型与上次任务决策。
- `/model-route preview <task>`：预览评分与路由，不发送模型请求。
- `/model-route off`：关闭当前会话的自动路由。
- `/model-route auto`：重新启用。
- `/model-route report`：按路由及当前窗口显示用量。
- `/model-route good` 或 `/model-route bad`：评价当前会话最近一次已测量请求。

请求完成不会自动计为正确。评价成功率只使用明确的 `good` 与 `bad` 反馈。

## 记账

价格使用每百万 token 的整数微美元。输入、缓存读取、缓存写入和输出是互不重叠的桶。测量数据保存精确的整数皮美元总额，仅在显示时转换，因此重复的小额请求不会因逐次取整而丢失现金成本。

订阅配额内部使用精确整数纳单位，配置采用毫单位权重。每个模型可设置请求、输入、缓存读取、缓存写入与输出权重。`windowHours` 和 `windowAnchor` 定义固定窗口；`quotaLimitMilliUnits` 支持配额不足时切换路由。任务准入时同步预留预计配额，结算时替换为实际用量，避免同一 DSH 进程中的竞争任务重复消费同一剩余额度。未使用的预留在步骤或回合边界以及销毁时释放。若结算跨越窗口边界，用量仍归属准入窗口。本地失败且没有提供商用量的请求会释放预留，并记录零实际配额。可选 `windowCostMicroUsd` 将套餐窗口价格以精确有理数分摊到已耗配额，用于等值成本比较；该值不是边际现金支出。

报告分别显示：

- 实际按量付费用现金与订阅用量；
- 按路由累计值与当前订阅窗口；
- 每秒输出 token、每千输出 token 现金成本、每配额单位输出 token；
- 传输完成状态与用户评价成功率。

测量数据默认保存到当前 DSH 配置下的 `.model-router/metrics-v2.json`，采用带版本校验的 JSON。DSH 的加锁原子写入工具串行化写入者，并把待写测量重放到最新磁盘状态，避免一个进程覆盖另一个进程已记录的用量。`lockWaitMs` 限制写入锁等待时间。已有文件损坏时插件停止加载，不覆盖原文件。后续写入失败会记录日志，并显示在报告中。

## 健康检查

被动健康监控始终使用启动验证与真实请求结果。失败请求使路由降级；`health.failureThreshold` 次连续失败使路由不可选择，直到 `health.retryAfterMs` 冷却结束。完成请求会恢复健康，除非延迟达到 `health.degradedLatencyMs`。用户取消不算提供商故障。只保留结构化故障代码，不保留原始提供商消息、提示、响应或凭据。

主动探测默认关闭。对单个模型设置 `healthProbe: true` 后，按 `health.probeIntervalMs` 执行有界单 token 探测，并受 `health.probeTimeoutMs` 与 `health.probeMaxOutputTokens` 限制。探测不会重叠，销毁时中止，其用量计入请求、现金和配额。启用可能产生费用或消耗订阅配额。仪表盘刷新本身不会探测。

`dailyRetentionDays` 限制 UTC 每日用量桶。旧 v2 文件以空的每日和健康部分加载，已有总量保持不变。

## 限制

- 任务重度评分是透明启发式规则，不是语义模型评测。请按工作负载调整 `classification`。
- 路由估算使用新任务文本和配置的输出估算，不使用完整会话。实际报告采用提供商在流中报告的用量。
- 订阅配额由配置权重估算。DSH 无法从模型名推导提供商隐藏的配额规则或套餐类型。失败或中止的流若缺少用量，实际配额按零计算。
- 共享同一配置文件的多个 DSH 进程会合并已提交测量。准入预留仅在进程内有效，不同进程同时准入任务不会全局串行化。
- 未配置路由仍报告 token 与延迟，但不会虚构现金、配额或等值金额。
- 只测量 agent-loop 请求，不包括会话标题等辅助调用。
- 推理 token 保存在测量数据中，但不会重复计费；提供商已将其计入输出总量。
